# AI-Powered Personalized Virtual Travel Guide

A Flask web app that generates AI-assisted travel itineraries. When a Gemini API key is
configured, Gemini itself suggests real destinations (not limited to a fixed list) and
builds a full, practical day-by-day plan with real calendar dates; without one, a local
scoring engine picks from the built-in destination dataset instead — either way you get
a complete itinerary with a budget breakdown, hotel/restaurant recommendations, a packing
list, and PDF export. All backed by a free-tier stack (Postgres via Neon, image storage
via Cloudinary, hosting via Vercel).

**Live**: https://ai-travel-guide-khaki.vercel.app/ · Demo login: `demo@travelguide.ai` / `demo1234`

## Features
- AI itinerary generation (Gemini, with a deterministic local fallback) — dates, multi-destination trips, practical pacing
- Destination browsing, search/filters, favorites, ratings & reviews (with photo uploads)
- Hotels & restaurants per destination
- Budget breakdown chart, packing list, emergency info, local customs
- Leaflet/OpenStreetMap maps + live nearby-essentials lookup (hospitals, police, ATMs, fuel) via the Overpass API
- PDF itinerary export with a QR code linking to the destination
- Saved trips dashboard, profile editing, password reset (dev-mode — no email service required)
- Gemini-backed travel chatbot (falls back to canned replies if no key is set)

## Stack
- **App**: Flask, Flask-Login, Flask-WTF (CSRF)
- **Database**: Postgres (designed for [Neon](https://neon.tech)'s free tier — no card required, no expiry), accessed through a small connection pool (`psycopg_pool`)
- **File storage**: [Cloudinary](https://cloudinary.com) free tier (profile pictures, review photos)
- **Hosting**: [Vercel](https://vercel.com) free "Hobby" tier (serverless, no card required)
- **Optional AI/weather**: Gemini API, OpenWeather API — both work with generous free tiers; the app runs fine without either (falls back to local logic)

## 1. Run locally

You need a Postgres database even for local development — this app has no SQLite
fallback. The free options below cost nothing and take a few minutes.

### Create your free database (Neon)
1. Sign up at [neon.tech](https://neon.tech) (no card required)
2. Create a project → copy the connection string it gives you (starts with `postgresql://...?sslmode=require`)

### Create your free image storage (Cloudinary) — optional, only needed for uploads
1. Sign up at [cloudinary.com](https://cloudinary.com) (no card required)
2. From your dashboard, copy your **Cloud name**, **API Key**, and **API Secret**

### Configure and run
```bash
cp .env.example .env
# edit .env: paste your Neon DATABASE_URL, and Cloudinary credentials if you want uploads

pip install -r requirements.txt
python app.py
```
Open http://localhost:5000 — the database schema and seed destinations are created
automatically on first run.

Demo login: `demo@travelguide.ai` / `demo1234`

## 2. Deploy to Vercel (free, forever)

1. Push this project to a GitHub repo
2. Go to [vercel.com](https://vercel.com) → **New Project** → import the repo (no card required for the Hobby plan)
3. In the project's **Settings → Environment Variables**, add the same variables from your `.env`:
   - `SECRET_KEY` (generate a random string — don't reuse the local dev one)
   - `DATABASE_URL` (your Neon connection string)
   - `CLOUDINARY_CLOUD_NAME`, `CLOUDINARY_API_KEY`, `CLOUDINARY_API_SECRET`
   - `GEMINI_API_KEY`, `WEATHER_API_KEY` (optional)
4. Deploy. Vercel auto-detects `vercel.json` (`builds`/`routes` targeting `api/index.py`) and builds it as a Python serverless function.

That's it — no Docker, no server to manage, and nothing here requires a paid tier for
personal-scale usage.

### Why Neon + Cloudinary instead of SQLite + local files
Vercel's serverless functions have no persistent disk — every request can hit a fresh,
stateless container. SQLite and local file uploads would be wiped constantly. Neon
(Postgres) and Cloudinary are both external, persistent, and free, which is why the
data layer was migrated to them.

## Enable real Gemini itineraries (optional)
By default itineraries are generated by a local deterministic engine limited to the
built-in destination dataset (no API key needed). With `GEMINI_API_KEY` set:
1. Gemini suggests real destinations matching the traveler's preferences (not just the
   built-in dataset) and writes the full day-by-day plan itself, with real calendar dates
2. The itinerary page shows a "Gemini AI" badge instead of "Local recommendation engine"
3. The chatbot widget answers with real Gemini responses instead of canned replies

If the Gemini call fails for any reason (no key, bad response, rate limit), the app
automatically falls back to the local engine — itinerary generation never breaks.

## Enable real weather (optional)
Set `WEATHER_API_KEY` to an [OpenWeather](https://openweathermap.org/api) free-tier key.
Without it, the dashboard shows a static fallback forecast.

## Project shape
- `app.py` — Flask application (also the WSGI target for Vercel)
- `api/index.py` — Vercel serverless entrypoint
- `services/` — recommendation engine, Gemini (itinerary + chat), weather, nearby-POI (Overpass API), PDF export, static content
- `templates/` — UI pages
- `static/` — CSS and JavaScript assets
- `database/db.py` — Postgres schema, connection pool, and all queries
- `utils/uploads.py` — Cloudinary upload helper
- `docs/` — architecture and API notes

## Not included (deliberately out of scope for a personal project)
No admin panel (removed — it had no access control and wasn't worth gating for a
single-owner app), no OTP/email verification, no rate limiting, no Docker, no automated
test suite. Destination/hotel/restaurant data is managed by editing `database/db.py`'s
seed data directly rather than through a UI.
